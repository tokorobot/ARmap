# 校内ナビ（QRチェックポイント式 疑似ARナビ）

来校者（オープンスクール参加者・企業の方・保護者）向けの校内道案内Webアプリ。
校内に掲示したQRコードを読み取ると現在地が確定し、目的地までターンバイターン形式で案内する。

## 仕組み

- **QR = 位置チェックポイント**。事務室前（起点）と各階段の踊り場にのみ掲示する。
  曲がり角にはQR不要（経路グラフのデータとしてのみ存在）
- 案内は「廊下を直進 → 右に曲がり渡り廊下で2号館へ → 階段で3階へ」のステップカード形式。
  利用者が「次へ」で送る（屋内での連続測位はしない設計）
- QRスキャン直後のみ、疑似ARコンパス矢印で「最初の一歩の向き」を表示。
  方位センサー許可時は端末の向きに連動（鉄骨校舎では磁気が乱れるため補助扱い）

## 開発

```powershell
# ポータブルNodeにPATHを通してから（このPCの環境依存）
$env:Path = "$env:USERPROFILE\tools\nodejs;$env:Path"
npm run dev          # PCでの開発用
npm run dev:https    # スマホ実機テスト用（カメラ・センサーはHTTPS必須）
npm run build        # 型チェック + 本番ビルド
```

## データの直し方（現地確認で修正する想定の箇所）

すべて `src/data/graph.ts` に集約してある：

- `BUILDINGS` … 各棟の部屋名（北→南の順）・階段の位置
- `BRIDGES` … 渡り廊下の接続（現状は各棟の北端で接続と仮定）
- `QR_OVERRIDES` / `stairDefaultFacing` … QRを正面に見たときの方位（現地で実測して調整）

## QRコードの掲示

アプリの `#/print`（ホーム下部の「QRコード印刷」）から全QRポイントのカードを印刷できる。
**QRのURLは開いているアドレスから生成されるので、本番公開URLで開いてから印刷すること。**

## 未対応・今後

- 図書館・視聴覚室は暫定的に1号館の部屋として扱っている（実際は別棟なら要修正）
- デプロイはGitHub Pagesを想定（校内ネットワークではCloudflare Tunnel不可のため）
